# 功能清单发现

## 职责

执行【TEMPLATE·分析范式】定义的发现流程，产出「功能清单」，为后续编写 Quick Start、API 参考和 SE 分析提供统一输入

## 操作流程

### 1. 遵循分析范式

严格按【分析范式】规定的发现顺序执行，不区分项目规模，禁止仅凭目录结构推断功能：

1. **入口理解** — 阅读 README、入口文件、构建脚本等，形成候选功能列表
2. **Demo / Example 优先** — 完整阅读 Examples/、samples/、demo 等全部源文件，提取功能与 API 证据
3. **测试驱动** — 缺少 Demo 时完整阅读对应测试文件，提取功能边界与典型用法
4. **源码兜底** — 以上均缺失时从源码推断，并明确标注「推断所得」

### 2. 补充归属与依赖

读取项目定义文件（构建清单、依赖清单等）中的依赖声明，记录每个功能的归属工程与依赖；具体文件格式与字段以项目实际技术栈为准。

### 3. 生成功能清单

| 功能名 | 归属工程 | 对外 API 面 | 依赖 | 证据来源 | 覆盖率状态 |
|---|---|---|---|---|---|
| 用户注册 | 认证服务 | register(凭证) | 数据库驱动 | Demo | QS ✓ / API ✓ / SE ✓ |
| 数据导出 | 报表模块 | export(格式) | 模板引擎 | Test | QS ✓ / API — / SE — |
| 主题定制 | 渲染器 | setTheme(调色板) | — | *推断所得* | TODO |

### 4. 覆盖率状态机

每个功能携带「覆盖率状态」字段，追踪三个编写维度对它的覆盖进度。

- `TODO` — 已发现，尚未编写。
- `QS ✓` — 快速入门页已写（第 3 步）。`API ✓` — API 参考页已写（第 4 步）。`SE ✓` — SE 分析页已写（第 5 步）。
- 每完成一个维度就追加对应标记；例如 `QS ✓ / API ✓ / SE ✓`。

规则：

- **第 3、4、5 步在完成某功能对应维度后，必须立即更新该列**，不得留旧。
- **功能集合在本步之后冻结。** 第 3–5 步只允许标记状态，不得增删或改名功能。任何修正必须回填清单并复核。
- 功能清单是维护在 **Wiki_Root 之外**的工作产物（如 `CloudGlyph_Child_Git/.workflow/feature-inventory.md`），随第 8 步审核做对账。它每轮重新生成，未来模板同步将其清理属预期行为。

## 输出

- 「功能清单」表（功能名 / 归属工程 / 对外 API 面 / 依赖 / 证据来源 / 覆盖率状态）
- 该清单是后续【快速开始】【API 参考】【SE 分析】的唯一功能输入，三阶段不得另起一套功能划分，且必须持续维护「覆盖率状态」列
