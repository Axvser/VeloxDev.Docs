# 审核

## 职责

对产出物进行逐一审核与改正

## 审核任务指派

### 默认应委派给独立子代理

审核自己刚产出的内容极易自我放行：你已相信自己改对的地方、已确信正确的示例。只要运行环境能启动**独立审核者** —— 一个上下文未参与任何编写阶段、彼此独立的子代理（如 Claude：可启动随本 SKILL 安装的 `wiki-reviewer` 子代理，或任意全新上下文的子代理；其它宿主用其等价机制）—— 就必须把本阶段交给它。这是默认路径，不是优化项。让写作者给自己的 Review 打钩，往往等于一路放行；独立审核者没有这份偏袒。

交给审核者一份自足的简报：

- **路径** — Project_Root；各选定语言的 Wiki_Root；功能清单工作文件；校验脚本目录。
- **权限** — 只读。审核者只报告发现；由**写作者**负责修复。
- **指令** — 不要相信写作者的任何断言。代码真实性与公开 API 表面必须对照 Demo / 测试文件重新核验，绝不依据写作者的行文。所有机器校验器都要由审核者亲自运行（`validate-links.py`、`validate-structure.py`、`validate-titles.py`、`validate-plot.py`、`validate-plantuml.py --engine java`、`validate-mermaid.js`、`validate-katex.js`、`gen_tree.py`）并粘贴原始输出。依据功能清单独立产出「覆盖率对账矩阵」。
- **输出** — 带文件路径的、按严重度排序的 不通过/通过 清单，外加覆盖率对账矩阵。

报告返回后，**写作者只负责**分级处理并修复其中的问题——绝不"再自审一遍"然后把自己的发现清零。

### 无独立代理时的兜底

若平台无法启动独立审核者（单上下文宿主），则在当前进程内自审，但要假定自己会给自己的产出放水，并主动对冲：

- 每个机器校验器都运行，并引用其原始输出 —— 判"通过"要引用输出，而非意图。
- 对每个页面，指出"若自己不是作者就一定会质疑"的一件事，然后修复或给出理由。
- 「覆盖率对账矩阵」依据功能清单文件书写，而非凭记忆。
- 任何只能靠"作者本人确认"的项，一律降级为遗留项并如实标注。

## 检查清单

### 覆盖率对账矩阵（硬性关卡）

依据功能清单的「覆盖率状态」列构建矩阵。矩阵必须写入审核输出——它是交付物，不是内心演练。

| 功能 | 证据来源 | 快速入门 | API | SE分析 | 状态 |
|---|---|---|---|---|---|
| 用户注册 | Demo | ✅ | ✅ | ✅ | 通过 |
| 数据导出 | Test | ✅ | ✅ | ❌ 缺少数据流子页 | 不通过 |
| 主题定制 | *推断所得* | ✅ | ⚠️ 部分：仅 setTheme | ✅ | 通过（遗留） |

规则：

- **证据来源为 Demo / Test 的功能，三个维度（快速入门 / API / SE 分析）必须全部 ✅。任一 ❌ ⇒ 整个审核不通过。** 立即修正后重新审核。
- **仅「推断所得」功能可带有 ⚠️ 遗留项**，且每个遗留项必须写明一行原因（如「公开表面未被证据完全覆盖」）。
- 对账完成后把最终状态写回功能清单（`通过` / `不通过` / `遗留`）。
- 若清单仍为 `TODO` 或与已完成页面矛盾的陈旧状态 → 不通过；状态机未被遵守。

### 用法完整性审计

- [ ] 每个功能模块的快速入门是否覆盖了其最上层 API（特性/Fluent/扩展方法）
- [ ] API 参考是否覆盖了「功能清单」中找到的所有公开类型和成员
- [ ] 代码示例是否同时展示了**声明式**和**命令式**两种使用风格

### Demo 阅读验证（前置检查）

在开始逐页审计前，先确认编写阶段是否履行了强制完整阅读义务：

- [ ] 对每个有 Demo 的模块，确认文档中覆盖了**该模块 Demo 目录下所有源文件**所展示的使用模式，而非仅片段
- [ ] 对每个仅有测试的模块，确认文档覆盖了测试文件中的关键用法和边界情况
- [ ] 如有 Demo 但文档有明显缺失的模式 → **标记不通过**，要求 Agent 重新完整阅读 Demo 后补写

---

### 代码真实性验证（关键 — 逐页全面审计）

对 Wiki 的**每一页**，提取所有包含 API 引用的代码块。对每个引用：

- [ ] **发现优先级合规** — 确认代码示例优先来自 Demo 项目（优先级 1）或测试（优先级 2）。如果仅使用了优先级 3（从源码推断），确认已明确标注为*推断所得*。
- [ ] **类/方法名** — 搜索代码库确认每个类型和成员存在且**签名一致**
- [ ] **命名空间/模块路径** — 验证与实际项目结构及源码声明一致，不得臆造路径
- [ ] **方法参数和返回类型** — 交叉对比源码声明；文档必须符合实际
- [ ] **异常声明** — 如果文档列出了异常，确认它在方法签名或文档注释中存在
- [ ] **属性/字段名** — 文档中引用的每个属性或字段必须在声明的类型上存在
- [ ] **已移除/已过时 API** — 标记任何文档中对已弃用（deprecated）或已移除成员的引用
- [ ] **无编造代码** — 每个代码块必须可追溯到真实的源文件

---

### 可复现性抽检

- [ ] 每个快速入门都有强制「前置条件」块（SDK/运行时/包管理器版本、目标框架、所需服务）
- [ ] 前置条件取自工程声明的 `TargetFrameworks`/依赖最低版本——**而非** Demo 的运行时（Demo 只证明一种被验证过的配置，绝非最低版本）
- [ ] 每个编号步骤都有可观测的「预期结果」
- [ ] 完整代码块中**无 `...` 省略号**；每个标识符都定义于示例、前序步骤，或可追溯到真实文件
- [ ] 页面以「运行声明」页尾结束：`✅ 实际构建并运行`（记录输出）或 `⚠️ 未实际运行`（仅静态核验，已标注）
- [ ] 任何 `✅` 声明，其记录输出与该步骤声明的预期结果一致

### 图表与公式校验（真实引擎渲染 + 降级预检）

图表与公式必须由**真实渲染引擎**校验——这是基准真相，而非肉眼或启发式。**一次性准备**：在 `<CloudGlyph_Child_Git>/src/CloudGlyph/Assets/Docs/scripts/` 下运行 `npm install`（提供 mermaid/katex/jsdom）并把 `plantuml.jar` 放到脚本旁（或用 `--jar <路径>` 指定）。然后运行：

- [ ] **PlantUML（真实引擎）** — `python validate-plantuml.py <Wiki_Root> --engine java`；真实的 `plantuml.jar -checkonly` 必须无错误
- [ ] **Mermaid（真实解析器）** — `node validate-mermaid.js <Wiki_Root>`；真实的 `mermaid.parse` 不得抛异常
- [ ] **KaTeX（真实渲染器）** — `node validate-katex.js <Wiki_Root>`；任何 `$...$` / `$$...$$` 在 `katex.renderToString` 下不得抛异常
- [ ] **函数图像（结构校验）** — `python validate-plot.py <Wiki_Root>` 报告无 ERROR：每个 ```plot 正文都是 JSON 对象，`data` 是数组，且各表达式（`fn`/`x`/`y`/`r`）只使用渲染器白名单允许的字符
- [ ] **该画图就别用文字** — 对每个描述数学行为的页面（缓动函数族、衰减、响应曲线、分布），确认它**用 `plot` 画了出来**，而不是只列表或叙述。若一张缓动公式表本可以用一张图呈现形状，记 WARN，并明确写出该结论。
- [ ] 修复每个报告的 **ERROR** —— 真实引擎报错意味着图表/公式无法渲染，是权威结论
- [ ] **引擎不可用**（机器无 node/java）时，降级到无依赖的结构预检 `validate-plantuml.py` / `validate-mermaid.py` / `validate-katex.py` / `validate-plot.py`（启发式），并明确注明未运行真实渲染校验

### 标题与本地化审计（硬性关卡）

侧边栏渲染的是目录名，页面渲染的是标题与链接文字。两者都由人阅读，因此都必须是**标题**而非路径，且都必须**是读者所用语言的**。

- [ ] **可见文字中不得出现数字前缀** — `python validate-titles.py <content 根目录>` 报告无 ERROR。它会揪出流入链接文字、标题或 `<a>` 内层文本的 `NN_` 记号；链接**目标**豁免。任何命中都是缺陷：读者绝不应看到 `1_快速开始`，只能看到 `快速开始`。
- [ ] **每个页面标题都已翻译** — 在每种非默认语言树中，每个目录名要么是其英文对应项的译文，要么是字面代码标识符（`MVVM`、`AOP`、`MonoBehaviour`、`00_VeloxPropertyAttribute`——即在源码中确实作为类型/命名空间/API 名存在的记号）。未翻译的描述性目录名（`prerequisites`、`install`、`complete-code`、`attached-behaviors`、`patterns-overview`）是 ERROR。
- [ ] **例外须由源码证明，而非因为省事** — 对翻译树中每个原样保留的目录名，在【Project_Root】中检索该字面量是否确实作为类型、命名空间或 API 名存在。「这是个技术词」不构成理由，「它是 `VeloxDev.MVVM`」才构成理由。
- [ ] **标题与正文语言与页面所在语言一致** — 已翻译页面内出现未翻译的小节标题，与未翻译目录名是同一类缺陷。
- [ ] **没有任何标题重复其上方标题** — `python validate-titles.py` 还会报告「复述链」（`# 工作流系统 — 快速开始` / `## 工作流系统` / `### 快速开始`）与「维度回声」（紧跟 H1、只写出父维度名的标题）。修法是删掉重复的标题并把它下辖的子标题上提一级，绝不能删掉那一节内容。
- [ ] **跨语言语义对等** — 每种语言中处于某一树位置的页面，就是另一种语言中同一位置页面的译文。`validate-structure.py` 校验拓扑，措辞则由本项逐页核对。

### 欢迎页审计

- [ ] 整页就是模板正文**加别的什么都没有** —— 收尾 `</div>` 之后不得有说明段落、表格、功能清单、"浏览文档"栏目或仓库链接
- [ ] **每张功能卡片都是链接**（`<a class="feat-link" href="…">`），指向该功能在「快速开始」中的页面（该功能没有自己的页面时指向快速开始栏目概览），且样式表中存在 `.feat-link`，使链接不带上划线与颜色
- [ ] 没有圆点分隔的宣传语尾行（`· 无数据库 · 开源 · MIT`，即原先的 `.glow-dot` 行）
- [ ] 首屏链接文字不含数字前缀（见「标题与本地化审计」）

### 结构一致性

- [ ] 数字前缀符合约定（如 `01_`、`02_`）
- [ ] 每个页面目录（根目录和子页面）都存在 `index.md` —— 由 `validate-structure.py` 机器校验（见下），不要依赖 `gen_tree.py` 去补建
- [ ] 代码块缩进使用实际空格（Space）而非制表符（Tab），宽度与【编码风格约定】一致
- [ ] **链接** — 每个链接必须且只能是三类之一且能解析（见【链接与导航】）：外部 `http(s):`/`mailto:`/`tel:` 由系统应用打开；同语言跨页链接解析到同语言树内真实存在的页面目录；`#…` 锚点等于同页某标题的自动 slug。不得有其它本地/绝对/跨语言链接。
- [ ] **运行链接校验器** — `python validate-links.py <Wiki_Root>` 报告无 ERROR（每个 `#…` 匹配同文件真实标题 slug；每个跨页目标在同语言根下真实存在）
- [ ] **运行结构校验器** — `python validate-structure.py <content 根目录>` 报告无 ERROR。它机器校验其余没有独立门禁的结构规则：每个目录（根、中间、叶子）都含 `index.md`；**叶子页**保持在拆分预算内（约 300 行，含硬上限）——超限叶子页是 ERROR，提示你按大纲先行拆成 `NN_` 子页；**父级** index.md 是简短概览且**链接其每一个子页**（漏链即 ERROR）；跨选定语言的树形结构一致；同语言内 `1_*`（快速入门）与 `2_*`（API）顶层功能目录集合一致。`4_Copyright` 维下的页面与首行为 `<!-- cg:atomic -->` 的页面豁免行数预算。
- [ ] 超过**约 300 行 / 3 个主题**的页面已按大纲先行拆分为子页，父级 `index.md` 作为链接全部子页的概览/目录 —— 由 `validate-structure.py` 机器校验
- [ ] **清理过期条目** — 删除范围仅限于同时满足以下条件的页面目录：(a) 不在本次输出清单上；(b) 不是「上下文确认」扫描时记录的既有页面（上次运行的有效产出必须保留并就地更新）；(c) 不被任何保留页面链接——运行 `python validate-links.py <Wiki_Root>` 确认无保留页面指向它们。删除前必须逐条列出候选；若删除后使某个不再被保留页面引用的父目录变空，一并移除该目录。不得仅因本次运行未重写某个页面就删除它。

## 预提交流程

> **先指派审核** — 能启动独立审核子代理时，将下方整个检查清单委托给它（见「审核任务指派」）并修复其报告的问题；进程内兜底仅适用于无子代理的宿主。

1. 按检查清单逐项走查，发现问题的**立即修正**再继续下一项
2. 代码真实性发现问题 → 使用源码搜索确认签名后修正文档
3. 图表/公式/图像发现问题 → 运行真实引擎校验器（`validate-plantuml.py --engine java`、`validate-mermaid.js`、`validate-katex.js`）以及 `validate-plot.py`，修复每个 ERROR 直至干净
4. 链接发现问题 → 运行 `python validate-links.py <Wiki_Root>`，修复每个 ERROR 直至干净
5. 标题/本地化发现问题 → 运行 `python validate-titles.py <content 根目录>`（数字前缀泄漏进可见文字、目录标题未翻译）；修复每个 ERROR 直至干净，再走一遍「欢迎页审计」
6. 结构发现问题 → 运行 `python validate-structure.py <content 根目录>`（每个目录都有 index.md、跨语言树形一致、快速入门/API 功能集合一致）；修复每个 ERROR 直至干净
7. 对账「覆盖率对账矩阵」：若任一 Demo/Test 功能存在 ❌，或矩阵未产出，质量门不通过
8. 对快速入门页面执行「可复现性抽检」
9. 执行 `python gen_tree.py`，确认无遗漏页面（结构干净后不存在缺 index.md 的目录，故此处无需 `--strict`）
10. 运行项目的构建命令，确认编译通过
11. 所有项 ✅ 后，标记质量门通过
