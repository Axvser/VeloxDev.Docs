# API 参考

## 职责

对每个功能模块的所有**接口、类型、函数**进行全量展开，提供完整的 API 目录与签名参考。

## 编写原则

### 全量覆盖

API 参考不追求"深入"或"多种风格"，而是追求**不打折扣的完整性**：

- 列举模块中所有公开的类型（类、结构体、接口、枚举）
- 对每个类型，列出所有公开成员（方法、属性、事件、字段）
- 包含完整的签名、参数说明、返回值说明、异常声明

**覆盖是硬性关卡。** 功能清单中的每个功能都必须有 API 页。证据来源为 Demo / Test 的功能，其公开表面必须**全量枚举**——每个公开类型与成员，不得截断；*推断所得* 的功能页面须明确标注，仅允许在此类功能上部分覆盖。完成后重新扫描模块的公开表面并与文档 diff，任何遗漏的 API 都要列为显式残余项。

### API 来源

以【分析范式】产出的「功能清单」为准：证据来源为 Demo / Test 的功能，其 API 表面直接从对应 Demo、测试中提取；标注「推断所得」的功能，从源码签名整理并在文档中标注。

**更新功能清单** — 完成某个功能后，将其覆盖率状态置为 `API ✓`。

### 条目模板

每个公开成员按以下结构记录：

```markdown
### {TypeName}.{MemberName}

**签名：**
`{返回类型} {成员名称}({参数列表})`

| 参数 | 类型 | 说明 |
|---|---|---|
| `{param}` | `{Type}` | {说明} |

**返回值：** `{Type}` — {说明}

**异常：**
| 异常 | 条件 |
|---|---|
| `{ExceptionType}` | {触发条件} |

**代码示例：**
```text
// 来源：[Demo/测试/源码推断]
result = instance.method(value);
```

优先给出**真实输入值→真实输出**的具体调用。若示例需要环境准备（依赖、服务注册），引用该功能的快速入门页，而不是重复展开。

**备注：**
- {补充说明}
```

### 组织方式

按类型分组，类型内按成员类型排序（属性优先，方法次之）：

```markdown
## {包/命名空间}

### 类：{ClassName}

#### 属性

| 名称 | 类型 | 说明 |
|---|---|---|
| `{Name}` | `{Type}` | {说明} |

#### 方法

（按条目模板逐个展开）

### 接口：{InterfaceName}

...
```

### 输出位置

```
Wiki_Root/2_API/00_{功能}/
├── index.md                    ← 概览
├── 00_{包/命名空间A}/
│   └── index.md
├── 01_{包/命名空间B}/
│   └── index.md
└── ...
```

> 功能目录名必须取自功能清单，且在 `1_快速开始`、`2_API`、`3_SE分析` 三棵树中完全一致。

> 当命名空间或功能 API 页预计超过约 300 行时，进一步按类型拆分：`2_API/00_{功能}/00_{命名空间}/00_{类型}/index.md`（命名空间较少时可直接 `2_API/00_{功能}/00_{类型}/index.md`）。

## 写入后操作

编写 API 文档后：

- [ ] **更新功能清单** — 将已编写功能的覆盖率状态置为 `API ✓`（见模块发现阶段）
- [ ] **重新生成导航索引** — 运行树生成脚本（如 `python gen_tree.py`）重建 tree.json
- [ ] **构建项目** — 运行项目的构建命令验证新内容正确嵌入
