# 快速开始

## 职责

为每个功能模块编写可独立运行的上手教程，用上层封装搭建一个真实可用的完整示例。

## 编写原则

### 完整可运行

Quick Start 的目标不是展示最精简的代码片段，而是带领读者从零到一地构建一个**实际可运行**的项目或功能。每个 Quick Start 应当：

- **有始有终** — 从项目创建/引入依赖开始，到验证功能正常结束
- **可复制** — 读者逐步骤操作后能获得一个可运行的程序
- **实用导向** — 解决一个真实的业务场景或功能需求

### 优先使用上层封装

使用模块提供的最高层 API（特性、扩展方法、Fluent API、基类），让读者看到的是**用起来长什么样**，而非**内部怎么实现**。底层接口派生和手动实现留给 API 参考。

### 素材来源

直接使用【分析范式】产出的「功能清单」：清单已标注每个功能的证据来源（Demo / Test / 推断）。取示例时按证据来源优先——有 Demo 则完整读取其全部源文件，其次为测试；标注「推断所得」的功能，其示例必须在文中注明，不重复进行功能发现。

### 可复现性契约

每个快速入门都是一份**人类可端到端复现的契约**。除下述结构外，还须遵守：

- **前置条件为强制项，且必须从构建元数据推导，而非从 Demo 推导** — 读取工程声明的 `TargetFrameworks` / `TargetFramework` 与依赖最低版本（csproj/工程文件、包清单），据此给出实际支持的目标框架、SDK/运行时与包版本。Demo 或测试只证明某一种*被验证过*的配置，绝不等于最低支持版本。所需服务附获取/启动方式。
- **每个编号步骤都给出可观测的「预期结果」** — 读者完成该步后能看到/听到/验证到什么，而非只在最后。
- **完整代码为单一最小可运行块** — 禁止 `...` 省略号；符号自洽：每个用到的标识符都定义于本示例、前序步骤，或可追溯到真实文件（标注路径）。
- **运行声明为强制项** — 页面必须以如实声明结尾：编写者是否实际构建运行过（✅ 附记录输出），或仅静态核验（⚠️）。

### 子页面（默认拆分）

功能的快速入门通常应**拆分为子页面**，而不是单个长页面。当页面预计超过**约 300 行**或涵盖**3 个以上不同主题**时拆分——按步骤或按操作分组：

```
00_{功能}/                        ← 概览 + 目录
├── index.md
├── 00_前置条件/
├── 01_安装配置/
├── 02_{操作A}/
├── 03_{操作B}/
└── 09_验证/                     ← 验证 + 完整代码 + 运行声明
```

- 每个子页保留各自的「预期结果」断言。
- 父级 `index.md` 是链接子页的简短概览，不要在其中重复子页正文。
- 「运行声明」页尾保留在最后一个内容页（即包含完整代码的页面）末尾。

### 结构

```
# {功能名称}

## 快速开始

### 1. 前置条件

- **支持目标取自工程声明的 `TargetFrameworks`**（如 `netstandard2.0;net6.0`）——Demo 的运行时只是*被验证过*的配置，绝不等于要求
- {SDK/运行时}：由支持目标决定所需版本（如 `net6.0` 需要 .NET SDK 6.0+）
- {包管理器}：版本
- {所需服务}：（如运行的数据库、API Key）及获取/启动方式
- 若任何前置条件无法在本地核验，下文「运行声明」必须标记 ⚠️。

### 2. 安装/引入依赖

如何安装/引入依赖（按项目技术栈使用对应的包管理器）

**预期结果：** {可观测结果，如包出现在清单中 / 命令退出码为 0}

### 3. 基础配置/注册

注册服务、创建实例、初始化配置等

**预期结果：** {如对象成功构造、服务启动、配置加载}

### 4. 核心用法（逐步构建）

按步骤组合上层 API，从简单到完整，每一步都有可运行代码

**预期结果：** {如输出值、界面状态、HTTP 状态码}

### 5. 验证

如何运行并验证功能正常（预期输出、界面效果等）

### 6. 完整代码

单一最小完整可运行代码块。禁止 `...` 省略号；符号自洽：每个用到的标识符都定义于本示例、前序步骤，或可追溯到真实文件（标注路径）。

### 7. 运行声明

- ✅ 实际构建并运行于 {日期}；记录输出：{粘贴实际输出}
- 或 ⚠️ 未实际运行——仅静态核验。请如实标注；该声明即可复现性契约。
```

### 输出位置

```
Wiki_Root/1_快速开始/
├── index.md                    ← 概览
├── 00_{功能A}/
│   └── index.md
├── 01_{功能B}/
│   └── index.md
└── ...
```

> 目录名必须取自功能清单，且在 `1_快速开始`、`2_API`、`3_SE分析` 三棵树中完全一致（跨维度一致性）。

## 写入后操作

编写快速入门内容后：

- [ ] **更新功能清单** — 将该功能的覆盖率状态置为 `QS ✓`（见功能发现）
- [ ] **重新生成导航索引** — 运行树生成脚本（如 `python gen_tree.py`）重建 tree.json
- [ ] **构建项目** — 运行项目的构建命令验证新内容正确嵌入
