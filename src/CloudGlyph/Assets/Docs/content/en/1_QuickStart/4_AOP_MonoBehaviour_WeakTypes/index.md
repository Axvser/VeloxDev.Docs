# AOP, MonoBehaviour & WeakTypes — Quick Start

This page bundles three cross-cutting subsystems of `VeloxDev.Core`:

- **AOP** — runtime aspect-oriented interception built on a generated `DispatchProxy`. Compile-time only for modern .NET: every runtime source file is wrapped in `#if NET`.
- **MonoBehaviour** — a Unity-style frame loop (`Update` / `LateUpdate` / `FixedUpdate`) driven by dedicated background threads (or async tasks on WASM).
- **WeakTypes** — weak-reference collections and event wrappers that let the GC reclaim subscriber / cache targets.

## AOP — Quick Start

### 1. Install

Add the `VeloxDev.Core` NuGet package. The package contains the runtime (`VeloxDev.AspectOriented`) and depends on the source generator `VeloxDev.Core.Generator`, which emits the proxy interface and the `Aop()` extension at compile time.

> The AOP runtime is compiled only for the `net5.0+` targets of the package (`#if NET`). It is not available on the `netstandard2.0` / `netframework4.6.1` targets.

### 2. Mark members with `[AspectOriented]` + define VM

Mark fields / properties / methods of a `partial` class with `[AspectOriented]`. `[VeloxProperty]` (from `VeloxDev.MVVM`) turns a backing field into an observable property, and the generator exposes both as interceptable members.

```csharp
using System.Collections.ObjectModel;
using System.Collections.Specialized;
using VeloxDev.AspectOriented;
using VeloxDev.MVVM;

namespace Demo;

public partial class TeamViewModel
{
    [VeloxProperty][AspectOriented] private string _name = string.Empty;
    [VeloxProperty][AspectOriented] private ObservableCollection<MemberViewModel> _members = [];

    [AspectOriented]
    public void Reset()
    {
        Name = string.Empty;
        Members.Clear();
    }

    [AspectOriented]
    public void AOP_OnMemberAdded(object? sender, NotifyCollectionChangedEventArgs e)
    {
        if (e.Action != NotifyCollectionChangedAction.Add) return;
    }
}
```

> Source: `Examples/AOP/WPF/Demo/TeamViewModel.cs` lines 16-53 (subset).

The generator produces an interface `VeloxDev.AopInterfaces.TeamViewModel_Demo_Aop : IAspectOriented` (generated by `AopInterface.cs`, name built at line 30) and a cached `Aop()` extension (generated by `AopWriter.cs`, lines 75-87). The proxy instance is created once per target and cached in a `ConditionalWeakTable` (`AopCache.Resolve`).

### 3. Attach start / coverage / end hooks via `Aop().SetProxy(...)`

```csharp
private static void ConfigureAOP(TeamViewModel data)
{
    var p = data.Aop();

    // start hook: fires BEFORE Name is read
    p.SetProxy(ProxyMembers.Getter,
        nameof(TeamViewModel.Name),
        (_, _) => { MessageBox.Show($"a read operation happened at [{DateTime.Now}]"); return null; },
        null,
        null);

    // end hook: fires AFTER Name was written
    p.SetProxy(ProxyMembers.Setter,
        nameof(TeamViewModel.Name),
        null,
        null,
        (p, _) => { MessageBox.Show($"the name of team has been changed to {p?[0]}"); return null; });

    // coverage hook: replaces the original Reset() logic
    p.SetProxy(ProxyMembers.Method,
        nameof(TeamViewModel.Reset),
        null,
        (_, _) => { MessageBox.Show($"the default Reset() has been cancelled"); return null; },
        null);
}
```

> Source: `Examples/AOP/WPF/Demo/MainWindow.xaml.cs` lines 45-95 (subset).

`SetProxy(ProxyMembers.Getter|Setter|Method, memberName, start, coverage, end)` registers a `(ProxyHandler?, ProxyHandler?, ProxyHandler?)` triple (see `ProxyEx.cs` lines 26-41). Each handler has the shape `object? ProxyHandler(object?[]? parameters, object? previous)`. A non-null `coverage` handler replaces the original logic; when it is `null`, `ProxyInstance.Invoke` falls back to reflection over the real target (see `ProxyInstance.cs` lines 23-53).

### 4. Verification

Call the members through the proxy and observe the hook order:

```csharp
var team = _teamData.Aop();
_ = team.Name;                       // getter start hook -> MessageBox
team.Name = "New Team Name";         // setter end hook   -> MessageBox
team.Reset();                        // coverage hook     -> default cancelled
team.Members.Add(new MemberViewModel() { Name = "Jack" });  // AOP_OnMemberAdded end hook
```

> Source: `Examples/AOP/WPF/Demo/MainWindow.xaml.cs` lines 18-42 (`Click0`..`Click4`).

## MonoBehaviour — Quick Start

### 1. Install

Same package: add `VeloxDev.Core`. The `VeloxDev.Core.Generator` source generator turns `[MonoBehaviour]` classes into `VeloxDev.MonoBehaviour.IMonoBehaviour` implementations.

### 2. Mark a class `[MonoBehaviour]` + partial Update / FixedUpdate

```csharp
using VeloxDev.TimeLine;

namespace Demo;

[MonoBehaviour]
public partial class MainWindow : Window
{
    [MonoBehaviour]
    private partial class PhysicsComponent
    {
        private int _updateCount = 0;
        private double _velocity = 0;
        private const double Gravity = 9.8;

        public PhysicsComponent() => InitializeMonoBehaviour();

        partial void Update(FrameEventArgs e)
        {
            _updateCount++;
            _velocity += Gravity * e.DeltaTime.TotalSeconds;
        }

        partial void FixedUpdate(FrameEventArgs e)
        {
            _fixedUpdateCount++;
        }
    }
}
```

> Source: `Examples/MonoBehaviour/WPF/Demo/MainWindow.xaml.cs` lines 8-33 (subset).

The generator emits `InitializeMonoBehaviour()` / `CloseMonoBehaviour()` (register/unregister) and declares the partial hooks `Awake`, `Start`, `Update(FrameEventArgs)`, `LateUpdate(FrameEventArgs)`, `FixedUpdate(FrameEventArgs)` (see `Writers/MonoWriter.cs` lines 80-120). Calling `InitializeMonoBehaviour()` registers the instance; the manager invokes `InvokeAwake` / `InvokeStart` on registration and then the frame callbacks.

### 3. Start the loop

```csharp
public MainWindow()
{
    InitializeComponent();
    Loaded += (s, e) =>
    {
        _physics = new PhysicsComponent();   // ctor calls InitializeMonoBehaviour()
        InitializeMonoBehaviour();           // register this window too
        MonoBehaviourManager.Start();        // start the "default" channel
    };

    Closing += async (s, e) =>
    {
        await MonoBehaviourManager.StopAsync();
    };
}
```

> Source: `Examples/MonoBehaviour/WPF/Demo/MainWindow.xaml.cs` lines 95-115 (subset).

### 4. Configure

Configuration is applied through the static manager (per channel; all methods take an optional `channel` parameter, defaulting to `"default"`):

```csharp
MonoBehaviourManager.SetTargetFPS(30, "game");       // clamp: 1..1000
MonoBehaviourManager.SetTimeScale(0.5f);             // clamp: 0..10
MonoBehaviourManager.SetFixedUpdateInterval(16);     // ms, clamp: 1..1000
```

> Source: `Src/Core/VeloxDev.Core/TimeLine/MonoBehaviourManager.cs` lines 184-210 (per-channel setters); demo line 50 calls `MonoBehaviourManager.SetTargetFPS(30,"game")` from inside `Update`.

### 5. Stop

```csharp
await MonoBehaviourManager.StopAsync();   // cancels both threads, resets stats, fires Stopped
```

### 6. Verification

Query live status from the loop or the UI thread:

```csharp
MonoBehaviourManager.IsRunning();
MonoBehaviourManager.CurrentFPS();
MonoBehaviourManager.ActiveBehaviorCount();
MonoBehaviourManager.IsUpdateThreadAlive();
MonoBehaviourManager.IsFixedUpdateThreadAlive();
```

> Source: `Examples/MonoBehaviour/WPF/Demo/MainWindow.xaml.cs` lines 182-188; query API at `MonoBehaviourManager.cs` lines 1070-1105.

## WeakTypes — Quick Start

> No demo project ships for WeakTypes; the usage below is **derived from the runtime source and the MSTest suite** and is marked *inferred*.

### 1. Install

Same `VeloxDev.Core` package; namespace `VeloxDev.WeakTypes`. All four types are available on every target framework of the package.

### 2. Leak-free events with `WeakDelegate`

*Inferred usage.* `WeakDelegate<TDelegate>` stores `WeakReference<Delegate>` instead of a strong reference, so an event publisher never roots its subscribers:

```csharp
using VeloxDev.WeakTypes;

var changed = new WeakDelegate<Action<string>>();
changed.AddHandler(name => Console.WriteLine($"name = {name}"));

// handler keeps working while the subscriber is alive
changed.Invoke(["VeloxDev"]);

// the combined delegate is cached; Clone() rebuilds it from live handlers
var snapshot = changed.Clone();
```

> Source: `Src/Core/VeloxDev.Core/WeakTypes/WeakDelegate.cs` lines 10-91; invocation shape `Invoke(object?[] objects)` line 68, verified by `WeakDelegateTests.cs` lines 9-19 (`wd.Invoke([42])`).

### 3. `WeakQueue` / `WeakStack`

*Inferred usage.* Elements are held weakly; `TryDequeue` / `TryPop` / `TryPeek` skip entries whose target was collected:

```csharp
var queue = new WeakQueue<string>();
queue.Enqueue("a");
queue.EnqueueRange(["b", "c"]);
if (queue.TryPeek(out var front)) { }      // "a", without removing
if (queue.TryDequeue(out var item)) { }    // "a"
queue.TrimExcess();

var stack = new WeakStack<string>();
stack.Push("a");
if (stack.TryPop(out var top)) { }         // "a"
```

> Source: `WeakQueue.cs` lines 34-120, `WeakStack.cs` lines 34-122; ordering verified by `WeakQueueTests.cs` lines 26-39 (FIFO) and `WeakStackTests.cs` lines 26-39 (LIFO).

### 4. `WeakCache`

*Inferred usage.* `WeakCache<TTargetKey, TCacheKey>` maps a weak key to a cache value via `ConditionalWeakTable`, with a periodic sweep that prunes collected targets:

```csharp
var cache = new WeakCache<ViewModel, Visual>();
cache.AddOrUpdate(vm, visual);

if (cache.TryGetCache(vm, out var v)) { }   // O(1) amortized
cache.ForeachCache((key, val) => Release(val));
cache.Remove(vm);
```

> Source: `WeakCache.cs` lines 14-79; behavior verified by `WeakCacheTests.cs` lines 9-87.
