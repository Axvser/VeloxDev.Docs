# 复杂度分析 — 过渡动画

令 $P$ = 一次过渡中声明的属性数，$k$ = 属性路径深度（表达式分段数），$B$ = 值类型之上的基类数，$I$ = 该类型实现的接口数。采样是连续的，由运行的 `ITimeSourceControl` 控节奏，因此没有预计算的帧数组：`ITransitionEffectCore.FPS` 只限制最大采样率，任何逐属性帧列表都不会被物化。

## 子页

- [插值](00_插值/index.md) —— 构建过渡、解析采样器、`Prepare`，以及每采样成本（包括过冲的代价，以及为什么只有五个有界通道采样器夹取 —— `Color`、`Size`、`SizeF`、`Rectangle`、`RectangleF` —— 而 `Quaternion` 钉住端点、其余外推）。
- [节拍器与调度器](01_节拍器与调度器/index.md) —— 每帧等待、时间轴读取、调度器查找与注册表，以及内存占用。

## 关键数字

| 操作 | 复杂度 | 频率 |
|---|---|---|
| `.Property(...)`（解析 + 插入 + 冲突检查） | $O(k) + O(P \cdot k)$ | 每次声明 |
| `TryGetInterpolator` —— 精确命中 | $O(1)$ | 每属性每次动画 |
| `TryGetInterpolator` —— 未命中 | $O(B + I)$ | 每属性每次动画 |
| `Prepare` 所有属性 | $O(P) + O(\sum m_j)$ | 每段每次动画 |
| 对一个采样施加所有属性 | $O(P)$ | 每帧 |
| 调度下一帧 | $O(1)$ 时间，首帧后 0 字节 | 每帧 |
| `FindOrCreate`（调度器查找） | $O(1)$ | 每段每次动画 |
| 路径冲突检查 | 每个声明值 $O(P \cdot k)$ | 每次声明 |

一个值得重复的结构性论断：**每条逐帧成本都是常数加 $O(P)$**，因为采样器、端点与编译后的访问器都已在 `Prepare` 中一次性解析。帧路径上没有任何东西解析、反射或分配闭包。
