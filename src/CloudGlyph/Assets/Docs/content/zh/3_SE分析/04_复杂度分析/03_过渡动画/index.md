# 复杂度分析 — 过渡动画

设 $P$ = 一次过渡声明的属性数，$k$ = 一条属性路径的深度（表达式分段数），$B$ = 某值类型之上的基类数，$I$ = 该类型实现的接口数。采样是连续的、由该趟的 `ITimeSourceControl` 定节拍，因此没有预先算好的帧数组：`ITransitionEffectCore.FPS` 约束最大采样率，并且任何逐属性的帧列表都不会被物化。

## 子页

- [interpolation](00_插值/index.md) —— 构建一次过渡、解析采样器、`Prepare`，以及每采样成本（含过冲的代价，以及为什么只有五个有界通道采样器钳位 —— `Color`、`Size`、`SizeF`、`Rectangle`、`RectangleF` —— 而 `Quaternion` 钉端点、其余外推）。
- [pacer-and-scheduler](01_节拍与调度器/index.md) —— 每帧等待、时间轴读取、调度器查找与注册表，以及内存占用。

## 关键数字

| 操作 | 复杂度 | 每 |
|---|---|---|
| `.Property(...)`（解析 + 插入 + 冲突检查） | $O(k) + O(P \cdot k)$ | 声明 |
| `TryGetInterpolator` —— 精确命中 | $O(1)$ | 每动画每属性 |
| `TryGetInterpolator` —— 未命中 | $O(B + I)$ | 每动画每属性 |
| `Prepare` 全部属性 | $O(P) + O(\sum m_j)$ | 每动画每分段 |
| 把一次采样施加到全部属性 | $O(P)$ | 帧 |
| 安排下一帧 | $O(1)$ 时间，首帧之后 0 字节 | 帧 |
| `FindOrCreate`（调度器查找） | $O(1)$ | 每动画每分段 |
| 路径冲突检查 | $O(P \cdot k)$ 每声明值 | 声明 |

有一条结构性论断值得重复：**每一处逐帧成本都是一个常数加上 $O(P)$**，因为采样器、端点与编译后的访问器都已在 `Prepare` 中一次性解析完毕。帧路径上没有任何东西在解析、查找、反射或分配闭包。
